# Private demo release plan

**Decision.** Prefer Option A on loopback. Use a trusted-network variant
only after verifying its firewall and certificate trust from the actual
viewer network. Keep Option B blocked pending an independently eligible
operator, separate approval, and evidence that requests cannot bypass the
access gateway. This plan authorizes no deployment.

| Criterion | A. Authenticated local demo | B. Conditional cloud staging |
| --- | --- | --- |
| Infrastructure cost | ₹0 incremental on existing Docker hardware | Free plans are plausible. An existing domain and eligible accounts are prerequisites. |
| Viewer access | Named Basic Auth credentials over verified TLS. Loopback default. | Named allowlist via gateway candidate. Requires verified origin enforcement. |
| Direct origin | Backend and DB unpublished. Start only the demo frontend. | **Blocked.** Render's public route and origin enforcement are unverified. |
| Demo actions | Prepared snapshots, source, graph and the four local search modes when indexed. | Prepared snapshots only. Hosted vector-assisted modes and AI stay disabled. |
| Writes | Method and endpoint allowlists deny mutation and answer generation. | Public ingestion must remain disabled. Gateway and origin must enforce read-only behavior. |
| Verification | Disposable local Docker smoke with certificate and auth fixtures. | Documentation review only. No control-plane or live-origin tests. |

## Option A — authenticated private Docker demo

### Access policy

The operator controls the host and grants one credential per invited
viewer. Loopback is the default and works for a screen-shared demo. For
direct trusted-network viewing, require a private interface and firewall
allowlist, a trusted certificate matching the private DNS name, and the
same authentication policy. Do not forward ports at a router or use a
public tunnel. Anyone with Docker or host admin access is inside the
trust boundary. Do not run an ordinary unprotected frontend listener or
publish the database or backend ports. Give viewers the exact approved
snapshot links. The demo database should contain only approved, already
prepared public sources. Basic Auth accounts share that dataset and do
not implement tenancy. Revoke access by removing the credential and
reloading or stopping the gateway. Keep access logs disabled.

The example [gateway](examples/private-demo.nginx.conf) uses TLS 1.2/1.3,
limits request sizes and rates, verifies Basic Auth for viewer content,
and permits only GET/HEAD plus a fixed API path allowlist. It strips the
gateway credentials before proxying and sets no-store. It denies
ingestion, generation, account deletion and other mutation routes.
The normal UI can still display controls whose requests the gateway blocks.
Demonstrate a local saved answer screenshot if needed. Do not enable
generation just for the demo.

### Operator preparation and launch

Run from the repository root in PowerShell. Use a separate, operator
approved database with only prepared demo snapshots. Set
`POSTGRES_PASSWORD` privately before starting any persistent database.
Use the existing pinned ingester privately and the index commands below,
or restore an approved backup into this isolated demo database and verify
its contents. Keep production data and frozen research storage separate.
If using a new empty project, prepare its snapshots before viewer access.
Never reuse a password from a fixture.

Provision a directory outside the checkout with restricted permissions,
and set `REPOBRAIN_DEMO_TLS_DIR` to it. Place the matching leaf certificate
and key at `cert.pem` and `key.pem`, and an Apache-format password file
at `users`. Store individually salted password hashes, such as bcrypt
generated by `htpasswd -B` with its interactive password prompt. Use
`htpasswd -cB` only for a new password file, then `htpasswd -B` to add
users. Keep files readable by the container's non-root Nginx worker
without granting access to unrelated host users. Provide the viewer
with a trusted CA or a verified local certificate fingerprint and CA file.
Do not disable certificate verification.

```powershell
$project = 'repobrain-private-demo'
$stack = @('-p', $project, '-f', 'compose.yaml', '-f', 'compose.frontend.yaml', '-f', 'compose.private.yaml')
# Optional, when showing all four search modes and pinned model files already exist.
# $stack += @('-f', 'compose.vector.yaml')
docker compose @stack up -d --wait db
docker compose @stack run --rm --no-deps backend alembic upgrade head
if ($LASTEXITCODE) { throw 'Migration failed' }

# Use the UUID of a completed snapshot prepared privately in this database.
$snapshot = ([guid]$env:REPOBRAIN_DEMO_SNAPSHOT).ToString()
docker compose @stack run --rm --no-deps backend python -m repobrain.graph $snapshot
docker compose @stack run --rm --no-deps backend python -m repobrain.search $snapshot
# For all four modes also build the vector index with the override enabled.
# docker compose @stack run --rm --no-deps backend python -m repobrain.search.vector_cli $snapshot

docker compose @stack up -d --wait --build backend
docker compose @stack build frontend
$tls = (Resolve-Path $env:REPOBRAIN_DEMO_TLS_DIR).Path
$config = (Resolve-Path docs/examples/private-demo.nginx.conf).Path
docker run --rm --name repobrain-private-gateway --network "${project}_default" `
  -p '127.0.0.1:8443:8443' --read-only --tmpfs /tmp `
  --security-opt no-new-privileges --memory 128m --pids-limit 64 `
  -v "${tls}:/run/demo:ro" -v "${config}:/etc/nginx/nginx.conf:ro" `
  "${project}-frontend"
```

Stop if any preparation or build fails. In another PowerShell terminal,
verify the port list and use the real trusted CA file. The authenticated
curl command prompts for the named viewer's password. Do not pass real
passwords on the command line.

```powershell
docker port repobrain-private-gateway
$base = 'https://localhost:8443'
$ca = $env:REPOBRAIN_DEMO_CA_FILE
$snapshot = ([guid]$env:REPOBRAIN_DEMO_SNAPSHOT).ToString()
curl.exe --cacert $ca -sS -o NUL -w '%{http_code}' "$base/"
curl.exe --cacert $ca --user $env:REPOBRAIN_DEMO_VIEWER "$base/api/v1/snapshots/$snapshot/graph"
curl.exe --cacert $ca --user $env:REPOBRAIN_DEMO_VIEWER -X POST -sS -o NUL -w '%{http_code}' "$base/api/v1/repositories/ingestions"
```

Expect 401, graph JSON with 200, and 405 respectively. Verify that
`docker compose @stack ps` lists no host ports for backend or database,
and no ordinary frontend service is running. Automation from the root
is `pwsh -NoProfile -File tests/private_demo_smoke.ps1`. It starts only
disposable test services, uses an ephemeral TLS certificate and random
test password, and verifies the denial and allowed paths without a cloud
account. It does not test a real trust domain or private-network firewall.
Stop the gateway with Ctrl+C and run `docker compose @stack down`.
Preserve persistent volumes.

## Option B — conditional cloud staging

Cloudflare Access is a candidate with a Free allowance of up to 50
users. It can restrict a covered hostname to an identity allowlist.
Protect every UI and API hostname and path, with no bypass policy.
Render attaches its default service hostname even when a custom domain
is configured. Its documented subdomain-disable setting requires a
custom domain and should return 404 after activation. This blocks that
documented hostname only after the setting is verified. A custom domain
or Access policy alone provides no proof that the origin rejects
direct traffic. Render's inbound IP allowlists for web and static
services require higher plans. RepoBrain currently validates Supabase
JWTs and does not validate Cloudflare Access assertions. Hostname
configuration, CORS and the mere presence of an Access header cannot
substitute for enforced origin authorization. If there is no verified
private path or fail-closed origin enforcement for both services, stop.

[Cloudflare plans](https://www.cloudflare.com/plans/) ·
[Access origin validation](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/application-token/) ·
[Render domain settings](https://render.com/docs/custom-domains) ·
[Render IP rules](https://render.com/docs/inbound-ip-rules)

After separate approval, an independently eligible operator would use the
[staging runbook](saas-deployment.md), audit Free billing and domain
availability, verify Supabase migration and TLS, and stage protection
before audience access. No eligible account is assumed. Do not proceed
if any provider condition or the strict zero-cost boundary cannot be met.
No Cloudflare, Render, or Supabase configuration was applied here.

**Acceptance smoke for the operator's authorized staging URLs only.**
Use unauthenticated ordinary requests to check the intended public-facing
entry points before granting viewer access. Then use a browser as an invited
viewer and a second browser profile without an invitation. Expect denial at
every unauthenticated entry point and no access at the Render default
hostnames if disabled. An API 401 from RepoBrain alone proves app auth,
not that the edge blocked the request.

```powershell
foreach ($url in @($env:REPOBRAIN_STAGE_UI, $env:REPOBRAIN_STAGE_API,
                  $env:REPOBRAIN_STAGE_RENDER_UI, $env:REPOBRAIN_STAGE_RENDER_API)) {
  if (-not $url) { throw 'All reviewed staging endpoints are required' }
  curl.exe --silent --show-error --max-time 15 --output NUL --write-out '%{http_code}\n' $url
}
```

Verify origin enforcement with provider logs and an approved test plan.
No live origin protection has been established. Do not enable public
ingestion, account changes, or AI generation as part of cloud staging.

## Demo checklist

- Confirm invited viewers, prepared public snapshot UUIDs and backup scope.
- Verify a trusted TLS connection, unauthenticated denial, and no direct listeners.
- Check lexical search, graph navigation, and commit-pinned source. Show all
  four local search modes only when the pinned vector profile is prepared.
- Check denial of ingestion, generation and account mutation requests.
- Describe the frozen benchmark as preliminary. Keep all recorded results intact.
- Stop the gateway, revoke any one-off credentials, and preserve volumes.
